# Security & privacy

PeerPrep's public Privacy Policy (`front/src/pages/Privacy.jsx`) makes concrete claims about this behaviour. Treat
everything below as a contract: if you change it, update the policy in the same change and bump
`LEGAL.lastUpdated` in `front/src/features/legal/legalInfo.js`.

## Visibility rules

| Data | Who can see it | Enforced in |
|---|---|---|
| Email address | Only its owner (`/auth/me`, login, profile update) | `services/users.py` (`public_user`, `display_name`); test in `tests/test_hardening.py` |
| Name, photo, bio, level, join date | Anyone, without sign-in (`/auth/user/{id}`, `/badges/user/{id}`) | `auth.py` |
| Events and their details | Anyone | `events.py` |
| Attendee names and photos | Anyone (`/events/{id}/attendees/details`) | `events.py` |
| Chat messages, read counts | Event members only (HTTP + socket) | `event_chat.py` (`_require_member`, socket membership check) |
| Whiteboard | Event members only | `whiteboard.py` |
| Study materials | Event members only. Lists never include them; `GET /events/{id}` (and create/update responses) include them only when the caller is a member. Everyone gets `materials_count` | `services/event_queries.py` (`serialize_events(..., with_materials=True)`); tests in `tests/test_materials_visibility.py` |
| Presence / typing | Event members; memory only, never stored | `chat_state.py` |
| Focus timer, today's plan, focus minutes | Nobody but the browser: `localStorage` key `peerprep-focus:<userId|guest>`, never sent to the API | `front/src/features/focus/focusStore.js` |

Display name rule: the chosen `name`, otherwise the email's local part (the text before "@").

## Authentication

- Passwords: Argon2 (`passlib`), 8–128 characters. Login is case-insensitive on email.
- JWT HS256 signed with `SECRET_KEY`, `sub` = user id, lifetime `ACCESS_TOKEN_EXPIRE_MINUTES` (60). No refresh or
  revocation; signing out deletes the token client-side.
- Email verification is required before login (403 otherwise). With `VERIFY_LINK_FALLBACK=true` the link is returned
  in the API response when sending fails. **That defeats verification**, so set it to `false` once SMTP works in
  production.
- WebSockets authenticate via the `peerprep.bearer` subprotocol; URL tokens are rejected.

## Abuse protection

- Rate limits: see [BACKEND.md](BACKEND.md#rate-limits-appcorerate_limitpy). Account lockout is checked before the
  password, so a locked account doesn't reveal whether a guess was right. Known trade-off: anyone can lock an account
  for 15 min by failing 10 times.
- Request bodies over 60 MB → 413. Field caps live in the schemas (see BACKEND.md).
- Whiteboard: ≤5000 elements per board, ≤500 per batch, ≤200 KB per element.
- AI: sign-in required, 20 calls per user per hour, input length caps.

## Input that reaches other users' browsers

- `photo_url`, `cover_image_url`: `data:image/(png|jpeg|gif|webp);base64,...` (≤5 MB) or `https://` (≤2048 chars).
- `study_materials[].data`: must be a `data:<mime>;base64,` URL. The frontend also renders only `data:` hrefs.
- Text is rendered by React (escaped). Never use `dangerouslySetInnerHTML` with user content.

## Headers

- **API** (`back/app/core/http.py`): `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`,
  `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` (except docs), plus HSTS when
  `ENVIRONMENT=production`. Interactive docs (`/docs`, `/redoc`, `/openapi.json`) are disabled in production.
- **Site** (`front/vercel.json`): strict CSP (`script-src 'self'`, no inline scripts; `connect-src` = self + the
  Render API over https/wss; `img-src` self/data/blob/https; `frame-ancestors 'none'`), HSTS, nosniff, DENY,
  referrer and permissions policies, immutable caching for `/assets/*`.
- CORS: `CORS_ORIGINS` (exact) + `CORS_ORIGIN_REGEX` (Vercel previews for the owner's account only).

## Secrets

- `back/.env` and `back/.secret_key` are git-ignored; `back/.env.example` documents every variable.
- Production secrets live in Render's environment (`SECRET_KEY` generated by the blueprint, `DATABASE_URL`,
  `OPENAI_API_KEY`, `EMAIL_PASS`, `ADMIN_PASSWORD`) and in Vercel (`VITE_API_BASE_URL` only; it's public by nature).
- The admin account gets a random password unless `ADMIN_PASSWORD` is ≥12 characters. Existing admin rows are never
  changed by config.
- Never paste connection strings, keys or passwords into code, logs, docs or chat.

## Third parties and data flows

| Party | Receives | When |
|---|---|---|
| Render (EU) | everything the API handles | always |
| Neon (EU, AWS Frankfurt) | the database | always |
| Vercel (US/global) | visitors' IP, requested pages | loading the site |
| OpenAI (US) | the text/prompt typed into an AI helper | only when the user presses that button |
| SMTP provider (Gmail SMTP by default; to be confirmed) | recipient email + verification link | sign-up / resend |

No analytics, ads, trackers, cookies or third-party fonts. Covers that are `https://` URLs (only the seeded sample
events) load from that host.

## Legal pages

- `front/src/features/legal/legalInfo.js` holds the operator facts. `null` values render as visible "to be
  confirmed" markers (currently: postal address, governing country, email provider), and a notice appears on the
  legal pages while any are missing.
- `PROCESSORS` in that file feeds the Privacy Policy's provider table.
- Account deletion behaviour is described precisely in the Privacy Policy (section "Deleting your account") and
  implemented in `services/cleanup.py::delete_user_data`. Keep them consistent.
- The texts are drafts for professional legal review, not legal advice.
